# [进店却未进行过交易的顾客](https://leetcode.cn/problems/customer-who-visited-but-did-not-make-any-transactions/)

## 题目

`Visits` 表：

| Column Name  | Type |
|--------------|------|
| visit_id     | int  |
| customer_id  | int  |

visit_id 是该表的主键。该表包含光临过购物中心的顾客信息。

`Transactions` 表：

| Column Name    | Type |
|----------------|------|
| transaction_id | int  |
| visit_id       | int  |
| amount         | int  |

transaction_id 是该表的主键。该表包含 visit_id 期间进行的交易信息。

查找有光顾但没有任何交易的顾客的 customer_id，以及他们只光顾不交易的次数。

## 题解

> 用 `LEFT JOIN` 连接访问和交易记录，筛选 `transaction_id IS NULL` 的记录，再按 customer_id 分组统计

```sql
SELECT v.customer_id, COUNT(*) AS count_no_trans
FROM Visits v LEFT JOIN Transactions t
ON v.visit_id = t.visit_id
WHERE t.transaction_id IS NULL
GROUP BY v.customer_id;
```

## SQL 流程

### 原始表

Visits（左表）

| visit_id | customer_id |
|----------|-------------|
| 1        | 23          |
| 2        | 9           |
| 4        | 30          |
| 5        | 54          |
| 6        | 96          |
| 7        | 54          |
| 8        | 54          |

Transactions（右表）

| transaction_id | visit_id | amount |
|----------------|----------|--------|
| 2              | 5        | 310    |
| 3              | 5        | 300    |
| 9              | 5        | 200    |
| 12             | 1        | 910    |
| 13             | 2        | 970    |

### LEFT JOIN（笛卡尔积 + ON 筛选 + 左表保留）

对左表每一行，去右表找 `visit_id` 匹配的行。没找到的 → 右表全填 NULL：

| V.visit_id | V.customer_id | T.transaction_id | T.visit_id | T.amount |
|------------|---------------|------------------|------------|----------|
| 1          | 23            | 12               | 1          | 910      |
| 2          | 9             | 13               | 2          | 970      |
| 4          | 30            | NULL             | NULL       | NULL     |
| 5          | 54            | 2                | 5          | 310      |
| 5          | 54            | 3                | 5          | 300      |
| 5          | 54            | 9                | 5          | 200      |
| 6          | 96            | NULL             | NULL       | NULL     |
| 7          | 54            | NULL             | NULL       | NULL     |
| 8          | 54            | NULL             | NULL       | NULL     |

> visit_id=4, 6, 7, 8 在右表中没有匹配，所以右表三列全部是 NULL。

### WHERE transaction_id IS NULL

从上面 9 行中，只保留右表 `transaction_id` 为 NULL 的行：

| V.visit_id | V.customer_id | T.transaction_id | T.visit_id | T.amount |
|------------|---------------|------------------|------------|----------|
| 4          | 30            | NULL             | NULL       | NULL     |
| 6          | 96            | NULL             | NULL       | NULL     |
| 7          | 54            | NULL             | NULL       | NULL     |
| 8          | 54            | NULL             | NULL       | NULL     |

这就是"光顾了但没交易"的那些访问记录。

### GROUP BY customer_id

按 `customer_id` 分组：

- 30：1 行
- 96：1 行
- 54：2 行（visit_id=7 和 visit_id=8，两次光顾没交易）

### SELECT + COUNT(*)

| customer_id | count_no_trans |
|-------------|----------------|
| 30          | 1              |
| 54          | 2              |
| 96          | 1              |

---

## 关键要点

> `LEFT JOIN` + `IS NULL` 是找"有 A 无 B"的标准模式，比 `NOT IN` / `NOT EXISTS` 更直观，且能保留左侧表的所有记录用于后续统计
