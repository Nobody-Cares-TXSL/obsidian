# [每台机器的进程平均运行时间](https://leetcode.cn/problems/average-time-of-process-per-machine/)

## 题目

表：`Activity`

| Column Name   | Type  |
|---------------|-------|
| machine_id    | int   |
| process_id    | int   |
| activity_type | enum  |
| timestamp     | float |

`(machine_id, process_id, activity_type)` 是该表的主键。

`activity_type` 是枚举类型（`'start'`、`'end'`）。`timestamp` 是浮点型，代表当前时间（以秒为单位）。`'start'` 代表进程开始运行时间戳，`'end'` 代表进程终止运行时间戳。同一台机器同一进程有一对 start 和 end 时间戳，且 start 在 end 之前。

计算每台机器各自完成一个进程任务的平均耗时。结果包含 `machine_id` 和 `processing_time`（四舍五入保留 3 位小数）。

## 题解

### 解法一：自连接 JOIN

> 将 Activity 表与自身按 `machine_id` + `process_id` 关联，ON 条件中分别限定 `activity_type = 'start'` 和 `'end'`，配对后直接求时间差的平均值。

```sql
SELECT a1.machine_id,
    ROUND(AVG(a2.timestamp - a1.timestamp), 3) AS processing_time
FROM Activity a1 JOIN Activity a2
ON a1.machine_id = a2.machine_id
   AND a1.process_id = a2.process_id
   AND a1.activity_type = 'start'
   AND a2.activity_type = 'end'
GROUP BY a1.machine_id;
```

### 解法二：单表 SUM + IF + distinct去重

> 不连接表，直接在单表中用 `IF()` 将 start 时间戳取反，`SUM` 后得到所有进程的总耗时，再除以进程数。核心技巧：start 取负、end 取正，`SUM = (end1 - start1) + (end2 - start2)`。

```sql
SELECT machine_id,
    ROUND(
        SUM(IF(activity_type = 'start', -timestamp, timestamp))
        / COUNT(DISTINCT process_id),
        3) AS processing_time
FROM Activity
GROUP BY machine_id;
```

`COUNT(*) * 2` 也可以（每进程恰好 start + end 两行），但 `COUNT(DISTINCT process_id)` 更通用。

### 解法三：单表 SUM + IF + COUNT(*)

> 与解法二逻辑相同，用 `COUNT(*) * 2` 替代 `COUNT(DISTINCT process_id)` 来计算进程数。

```sql
SELECT machine_id,
    ROUND(
        SUM(IF(activity_type = 'start', -timestamp, timestamp))
        / COUNT(*) * 2,
        3) AS processing_time
FROM Activity
GROUP BY machine_id;
```

> 注意运算符优先级：`/ COUNT(*) * 2` 即 `(SUM / COUNT(*)) * 2`，从左到右计算。

### 解法四：单表 SUM + CASE WHEN

> 与解法二逻辑相同，用 `CASE WHEN` 替代 `IF()`。`CASE WHEN` 是标准 SQL 语法，兼容性更好（`IF()` 是 MySQL 特有）。

```sql
SELECT machine_id,
    ROUND(
        SUM(
            CASE
                WHEN activity_type = 'start' THEN -timestamp
                ELSE timestamp
            END
        )
        / COUNT(DISTINCT process_id),
        3) AS processing_time
FROM Activity
GROUP BY machine_id;
```

### 解法一：自连接 JOIN

### FROM + JOIN ON（自连接配对 start 与 end）

> 将 Activity 表与自身做 INNER JOIN，ON 同时匹配 `machine_id` + `process_id`，并分别限定 `a1.activity_type = 'start'`、`a2.activity_type = 'end'`。每个 start 行只能和一个 end 行配对（(machine_id, process_id, activity_type) 是主键，保证了唯一性）。

> end 行不会作为 a1 出现（ON 要求 `a1.activity_type = 'start'`），同理 start 行不会作为 a2 出现。8 行 → 4 行。

| machine_id | process_id | a1.timestamp (start) | a2.timestamp (end) |
|------------|------------|----------------------|--------------------|
| 0          | 0          | 0.712                | 1.520              |
| 0          | 1          | 3.140                | 4.120              |
| 1          | 0          | 0.550                | 1.550              |
| 1          | 1          | 0.430                | 1.420              |

### GROUP BY machine_id（按机器分组）

> JOIN 产生的 4 行按 `machine_id` 分成 2 组，每组内的行将一起参与聚合计算。

| 组 | machine_id | 包含的行 |
|----|------------|---------|
| 1  | 0          | process_id=0 (0.712→1.520)、process_id=1 (3.140→4.120) |
| 2  | 1          | process_id=0 (0.550→1.550)、process_id=1 (0.430→1.420) |

### SELECT：ROUND(AVG(a2.timestamp - a1.timestamp), 3)（计算平均值并输出）

> SELECT 是最后一步。对每组：① 逐行计算 `a2.timestamp - a1.timestamp`（时间差）；② `AVG` 求平均；③ `ROUND` 保留三位小数。

机器 0（2 行）：

| process_id | start | end   | a2.timestamp - a1.timestamp |
|------------|-------|-------|-----------------------------|
| 0          | 0.712 | 1.520 | 1.520 - 0.712 = **0.808**   |
| 1          | 3.140 | 4.120 | 4.120 - 3.140 = **0.980**   |

AVG(0.808, 0.980) = 1.788 / 2 = **0.894**

机器 1（2 行）：

| process_id | start | end   | a2.timestamp - a1.timestamp |
|------------|-------|-------|-----------------------------|
| 0          | 0.550 | 1.550 | 1.550 - 0.550 = **1.000**   |
| 1          | 0.430 | 1.420 | 1.420 - 0.430 = **0.990**   |

AVG(1.000, 0.990) = 1.990 / 2 = **0.995**

| machine_id | processing_time |
|------------|-----------------|
| 0          | 0.894           |
| 1          | 0.995           |

### 解法二/三/四：单表条件聚合

### FROM Activity（锁定主表）

> 单表查询，无 JOIN。原始 8 行数据直接进入后续处理。

### GROUP BY machine_id（按机器分组）

> 8 行按 `machine_id` 分成 2 组。

- 机器 0：4 行 — process_id 0 和 1 各有 start + end
- 机器 1：4 行 — 同上

### SELECT（三种解法的聚合公式各不相同）

> 三种解法共享同一个变换结果（start 取负、end 不变），区别仅在 SELECT 中的聚合公式：`IF` vs `CASE WHEN` 控制条件语法，`COUNT(DISTINCT)` vs `COUNT(*) * 2` 控制进程数计算。

> 核心技巧：start 取负、end 取正后，同一进程的两行相加恰好等于 `end - start`。例如机器 0 的进程 0：(-0.712) + 1.520 = 0.808。

| machine_id | process_id | activity_type | timestamp | 变换值 |
|------------|------------|---------------|-----------|--------|
| 0          | 0          | **start**    | 0.712     | -0.712 |
| 0          | 0          | end           | 1.520     | 1.520  |
| 0          | 1          | **start**    | 3.140     | -3.140 |
| 0          | 1          | end           | 4.120     | 4.120  |
| 1          | 0          | **start**    | 0.550     | -0.550 |
| 1          | 0          | end           | 1.550     | 1.550  |
| 1          | 1          | **start**    | 0.430     | -0.430 |
| 1          | 1          | end           | 1.420     | 1.420  |

> 加粗 `activity_type` 为 start 的行（timestamp 取负），其余 end 行保持不变。

#### 解法二：SUM(IF) / COUNT(DISTINCT)

> 用 `IF()` 判断条件，`COUNT(DISTINCT process_id)` 得到进程数。

```sql
SUM(IF(activity_type = 'start', -timestamp, timestamp)) / COUNT(DISTINCT process_id)
```

| machine_id | SUM（总耗时） | `COUNT(DISTINCT process_id)` | `ROUND(SUM / COUNT, 3)` |
|------------|---------------|---------------------------|-----------------------|
| 0          | 1.788         | 2                         | `ROUND(1.788 / 2, 3) = 0.894` |
| 1          | 1.990         | 2                         | `ROUND(1.990 / 2, 3) = 0.995` |

#### 解法三：SUM(IF) / COUNT(\*) \* 2

> 同样用 `IF()`，但用 `COUNT(*) * 2` 替代 `COUNT(DISTINCT)` 来推算进程数。运算符优先级：`(SUM / COUNT(*)) * 2`，从左到右。

```sql
SUM(IF(activity_type = 'start', -timestamp, timestamp)) / COUNT(*) * 2
```

| machine_id | SUM（总耗时） | `COUNT(*)` | `ROUND((SUM/COUNT(*)) * 2, 3)` |
|------------|---------------|------------|----------------------------------|
| 0          | 1.788         | 4          | `ROUND((1.788/4) * 2, 3) = 0.894` |
| 1          | 1.990         | 4          | `ROUND((1.990/4) * 2, 3) = 0.995` |

#### 解法四：SUM(CASE WHEN) / COUNT(DISTINCT)

> 用 `CASE WHEN` 替代 `IF()`（标准 SQL 语法，兼容性更好），聚合逻辑与解法二相同。

```sql
SUM(CASE WHEN activity_type = 'start' THEN -timestamp ELSE timestamp END) / COUNT(DISTINCT process_id)
```

> 变换值与解法二完全相同（`IF` 和 `CASE WHEN` 在本题产生相同结果），聚合公式与解法二相同：

| machine_id | SUM（总耗时） | `COUNT(DISTINCT process_id)` | `ROUND(SUM / COUNT, 3)` |
|------------|---------------|------------------------------|--------------------------|
| 0          | 1.788         | 2                            | `ROUND(1.788 / 2, 3) = 0.894` |
| 1          | 1.990         | 2                            | `ROUND(1.990 / 2, 3) = 0.995` |

## 关键要点

### IF() vs CASE WHEN

> `IF()` 是 MySQL 特有函数，`CASE WHEN` 是标准 SQL，跨数据库优先用后者。

| 写法 | 语法 | 兼容性 |
|------|------|--------|
| `IF(cond, a, b)` | `IF(条件, 真值, 假值)` | MySQL 独有 |
| `CASE WHEN` | `CASE WHEN cond THEN a ELSE b END` | 所有数据库 |

- 简单二选一用 `IF()` 更简洁，多条件分支用 `CASE WHEN`
- 面试/生产环境推荐 `CASE WHEN`，保证可移植性

### COUNT(*) vs COUNT(DISTINCT column)

> `COUNT(*)` 计算所有行数，`COUNT(DISTINCT column)` 计算某列去重后的行数。

- 本题每进程有 start + end 两行 → `COUNT(*)` = `进程数 × 2`
- `COUNT(DISTINCT process_id)` 直接得到进程数，不依赖"每进程恰好两行"
- 当数据可能有脏行（缺失 start 或 end）时，`COUNT(DISTINCT)` 更安全

### 条件聚合（Conditional Aggregation）

> 在聚合函数（SUM、AVG、COUNT）内嵌套条件判断，实现"按条件筛选后再聚合"的效果，避免写子查询或 JOIN。

```sql
-- 模式：SUM(IF(条件, 值, 0)) 或 SUM(CASE WHEN 条件 THEN 值 ELSE 0 END)
SUM(IF(activity_type = 'start', -timestamp, timestamp))
```

- 本题 start 取负、end 取正，SUM 后自动完成"end 之和 - start 之和"
- 适用场景：同一列不同行代表不同含义（如 start/end、收入/支出），需要分别处理后再聚合
